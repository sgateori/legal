Bastion Privacy Policy

App: Bastion (sh.bastion.app) · Developer: sgateori · Last updated: 2026-10-22

Bastion is a remote-access and terminal app. It connects to servers you choose (SSH, Mosh, VNC, RDP and others), can run Linux guests on your phone, and has an optional local endpoint that lets an AI agent you pair with control the app. It has no accounts, shows no ads and sells no data. This page says what is stored on your device and what leaves it.

What stays on your device

Connection profiles (host names, ports, user names, labels and options), known-host fingerprints, settings, the on-device log of agent calls (arguments redacted) and the rclone configuration are stored in the app's private storage. We cannot see them. They are excluded from Android backups and device transfers, and uninstalling the app deletes them.

Passwords, key passphrases and TOTP secrets are encrypted with AES-256-GCM using a key held in the Android Keystore. Private SSH keys and tunnel configuration text are encrypted with a separate Keystore key. The connection profile database itself, the known-host list, the settings and the rclone configuration file are not encrypted by the app and are protected only by Android's app sandbox. rclone obscures passwords in its configuration (this is reversible) and keeps cloud-provider sign-in tokens as plain text in that private file.

You can lock the app with biometrics or your device credential and turn on screen-capture protection. Backups are made only when you ask: an encrypted file that you save where you choose, or an automatic push to a remote you configured. Nothing is sent to us.

Where your connections go

Bastion connects to the servers, mail accounts, cloud providers and tunnel services you set up (for example SSH, VNC, RDP, SMB, SFTP, Proton or IMAP/SMTP mail, rclone cloud storage, Tailscale, NetBird, WireGuard and Cloudflare Access). This traffic goes directly between your phone and those hosts, never through us. Android's HTTP stack refuses cleartext traffic except to the phone itself (127.0.0.1 and localhost); that rule does not cover the native libraries or SSH sockets. If you use Cloudflare Access, an in-app sign-in page captures your Cloudflare Access cookie for that connection.

Downloads from third parties

When you take these actions, your phone connects to the following hosts, which can see your IP address. None of them is a service run by us.

  • Linux guests: when you install a distribution, Bastion downloads its root file system from github.com (proot-distro releases), dl-cdn.alpinelinux.org or kali.download. The download addresses are fixed in the app and each file is checked against a pinned SHA-256 hash. Inside a guest, that distribution's package manager then contacts its own mirrors.
  • Tails: only if you import the Tails VM preset, the image is fetched from download.tails.net.
  • Terminal fonts: fonts you pick are fetched from cdn.jsdelivr.net (or from a font address you enter yourself). The local media-stream page also loads a script (hls.js) from jsDelivr into your browser or player.
  • Single-packet authorization: only if you use that feature, api.ipify.org is asked for your public IP address.
  • Guest app skin: one optional skin file can be fetched from archive.org.

The AI agent endpoint (MCP)

This endpoint is off by default. When you turn it on, it listens on the phone's loopback address only (a LAN listener is a separate setting that is off by default). A new client must be approved by you before it gets a token, and you can unpair it at any time. Sensitive tools ask for your consent on each call or once per session, and every call is logged on your device.

Depending on the tool and your consent, an agent you paired can receive things such as a camera frame, a location fix, notification text, files, terminal contents or the clipboard. That data goes to the agent client you chose, not to us. What that client does with it is governed by that client's own terms.

Some tools are off until you enable them separately (agent file reads and queued terminal input). Optional Shizuku support, if you install and authorize Shizuku, lets the app grant itself permissions and read the device log.

Crash reports and anonymous usage (Firebase)

To fix crashes and see which features matter, Bastion uses Google Firebase Crashlytics and Firebase Analytics. Google acts as our processor. This is on by default, starts when you first open a release build, and you can turn it off at any time with one switch: Settings > Security & privacy > Share crash reports and usage statistics. It is always off in debug builds, and the switch controls both services.

Bastion does not deliberately send host names, ports, user names, key names, passwords, file contents, agent-tool arguments or results, clipboard or terminal contents, network names or IP addresses in these events or in the crash keys. The agent-tool name is sent only when it is one of the app's own registered tools.

The Firebase libraries also collect some standard data on their own: device model, operating system and app version, general events such as app opens and sessions, random per-install identifiers (the Firebase app-instance ID and the Crashlytics installation ID), and Google derives an approximate country or region from your IP address when the data arrives. These identifiers are not your advertising ID. Bastion does not use the advertising ID and its advertising-ID permission is removed from the app.

Limit: Bastion has no crash handler of its own for uncaught crashes, so when the app crashes with an unexpected error, the error text written by the system or a library is sent as it is. Such text can include a host name or user name, for example from a connection failure. Native (signal) crashes are not uploaded; they are only recorded on your device.

Data is encrypted in transit. It is kept by Firebase under Google's default retention. See Firebase privacy information and the Google Privacy Policy.

What we do not collect

We do not receive your connection profiles, passwords, keys, files, terminal output, clipboard, camera images, location, notifications, contacts or messages, and we run no server that stores them. Data you send to servers you chose, to cloud providers, or to an agent you paired does not pass through us. We do not sell data and do not use it for advertising.

Permissions

Internet, network state and multicast (connections and local-network discovery); foreground service (keeps connections alive while a notification is showing); notifications (connection and consent notices); wake lock and the battery-optimization exemption request (keep sessions alive with the screen off); biometrics (optional app lock); NFC and USB host (security keys); Bluetooth (Bluetooth and BLE serial consoles); camera and location (declared for the agent tools that capture a camera frame or a location fix, which ask for consent on each call, and location also for Bluetooth scanning on older Android versions); all-files access and legacy storage read (the SFTP file browser and USB drive mounts); install packages (opening the system installer for an APK you download or an agent installs with your consent); and receive boot completed (background work scheduling). Notification access is a separate special permission you grant in system settings, used only to let an agent list notifications. Bastion declares no contacts, SMS, phone or microphone permissions.

Your choices and deleting data

Use the switch above to stop crash and usage collection at any time. Pairing, the agent endpoint and each agent capability can be turned off in Settings. We have no account system, so we cannot look up your data by name. To ask us to delete reports from your install, email us the installation identifier or a description of when the crash happened, and we will delete what we can match. Uninstalling removes all local data.

Children

Bastion is a general-purpose tool and is not directed at children.
